# 旅程拼贴生成规则

本规则适用于所有旅程页面。目标是让地图保持真实，让记忆保持手作感；不同旅程更换数据，不更换视觉语法。

## 1. 输入数据

每段旅程必须提供：旅程名称、日期范围，以及按时间排序的地点。每个地点必须包含国家代码、经纬度、日期、照片、地点名称、「第一次」标题和记忆文本；服务端会据此匹配一级行政区。

照片识别阶段额外输出 `hasDetectedSubject`：画面中存在可稳定识别的人物或物体时为 `true`，纯风景或没有明确主体时为 `false`。

## 2. 地图与路径

- 使用真实一级行政区边界和地点经纬度生成局部地图，不允许手绘一个替代真实地理关系的假地图。
- 单省旅程只显示该一级行政区；跨省或跨地区旅程合并显示实际涉及的全部一级行政区，不额外铺开整个国家。
- 海面不填色，页面纸张就是地图背景；陆地使用低饱和青绿色纸片表现。
- 路径按地点日期顺序连接，使用平滑曲线而非折线。
- 地图、路径、照片和便签可以互相遮挡，以形成真实的拼贴层次。
- 地点圆点和地点名称始终位于最高层，任何内容都不能遮挡。

## 3. 照片处理

- `hasDetectedSubject = true`：提取人物或物体的最大连续主体轮廓，背景透明；轮廓外扩一圈不均匀的暖白色纸边。
- `hasDetectedSubject = false`：不抠图、不去天空；保留完整构图，中心裁成正方形，套用暖白拍立得相框。
- 不调用生成式图片模型改写用户照片，不新增、删除或重绘照片内容。
- 照片优先使用大尺寸，允许照片、便签和路线发生局部交叠。

## 4. 拼贴布局

- 单张拼贴不限制地点数量。超过基础槽位数量后，继续循环使用槽位并形成真实纸片堆栈，不分页。
- 使用 5 个稳定但不对称的基础照片槽位和便签槽位，避免生成规则网格；同槽位中的后续照片按记录顺序自然叠放。
- 第一张无主体的风景照片通常作为最大视觉锚点；主体抠图围绕路径分布。
- 便签放在照片之间的负空间中，不覆盖地点圆点或地点名称。

## 5. 交互

- 点击地点、照片或便签，统一激活同一个地点，并将对应照片和便签提升到拼贴顶层。
- 激活状态在原位置增强轮廓、阴影或色彩，不弹出覆盖地图的内容框。
- 地点始终是最明显、最稳定的点击入口；照片和便签是辅助入口。

## 6. 实现入口

- 通用拼贴组件：`src/components/JourneyCollageMap.tsx`
- 照片规则处理：`src/components/SmartPhotoCutout.tsx`
- 数据类型与规则常量：`src/lib/journey-collage.ts`

其他旅程页面只需构造 `JourneyCollageData` 并传入 `JourneyCollageMap`，不应复制或重写拼贴逻辑。
