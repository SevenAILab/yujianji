# 精神图景 B 侧后端交付方案

依据：[协作分工文档（2026-09-22 Day2）](https://ycni5kjxv9zb.feishu.cn/docx/HeJQdCTC7oehHWxbdAycvYMnnJf)。本任务是**照片到 GLB 3D 模型**，不生成 MP4 视频。目标仓库尚未在当前工作目录中；本文是实现和验收约定，代码应按协作文档进入目标仓库的 `scripts/pipeline/**`、`src/lib/spirit/**`、`public/assets/**`，通过 PR 合入。

## 当前实测与决策

现有独立 FastAPI 服务已接通 Tripo v3 并生成两个可解析的 PBR GLB：

| 样例 | Tripo 任务耗时 | 消耗 | 原始 GLB | 网格 |
| --- | ---: | ---: | ---: | ---: |
| 木质酒杯 | 5 分 14 秒 | 60 积分 | 58.2 MB | 约 190 万三角面 |
| 蘑菇生物 | 4 分 50 秒 | 60 积分 | 56.6 MB | 约 191 万三角面 |
| 陶狐狸摆件（合成遇见照片，standard） | 2 分 28 秒 | 30 积分 | 42.2 MB | 压缩后 11.76 万三角面 / 3.75 MB |

预览在 `examples/*-preview.webp`。这证明上传、异步任务、下载、GLB 解析通路可用，但**不满足文档的单张 60 秒目标**。陶狐狸用 ImageGen 合成照片并完成端到端测试及浏览器预览，和真实拍摄仍不同；此轮只做主体裁切，未开启透明背景抠图。今晚 B1 还需用至少一张真实照片跑通抠图及端到端计时，并记录质量截图。若只有路演演示，采用离线预生成，绝不在现场等待 Tripo。若产品仍坚持实时 ≤60 秒，另开标准/快速档与候选供应商的基准测试，不能用高质量档实测冒充达标。

## 数据与目录边界

`public/assets/encounters.json` 是唯一前后端数据契约。B 只按 `id` 补充 `cutoutUrl`、`model`、`rarity`，原有 `photoUrl`、`capturedAt`、`geo`、`label`、`firstSeen` 和 Seven 的 `quote` 必须原样保留。前端只读相对站点路径，例如 `/assets/models/<id>.glb`；Tripo 的临时签名 URL 不写入 JSON。

建议目录：

```text
scripts/pipeline/          批处理入口、Tripo 适配、缓存、几何后处理、校验、打印导出
src/lib/spirit/            Encounter 类型和运行时读取/校验
public/assets/encounters.json
public/assets/cutouts/<id>.png
public/assets/models/<id>.glb
public/assets/stack.json  A 烘焙后交付 B 使用
```

当前独立 API 服务可作为 Tripo 接口验证样机；演示站点无需实时调用它。批处理脚本应在目标仓库里落地并由仓库命令启动。

## B2 批量管线：先做稳定、可恢复

1. 读取 Seven 提供的 mock/真实 `Encounter`，校验唯一 `id`、图片可读取、`label` 和 `firstSeen`。标签已经由现有遇见集识别，不重复构建一套物品识别服务。
2. 按照片内容哈希 + 处理版本 + Tripo 参数生成缓存键。预处理修正 EXIF、裁切主体、可选透明底抠图；保存 `cutoutUrl`。失败图保留原图并记录需人工复核，不让一张坏图阻断整批。
3. 用有界并发（先 2 个）提交 Tripo；持久化每个任务的 `task_id`、状态、重试次数和错误。上传/查询可退避重试；付费的创建请求超时后状态标为“提交结果不明”，先查控制台/任务列表，不能盲目重交导致重复扣费。
4. 轮询成功后立即下载原始 GLB 到非 `public` 缓存目录，验证 GLB 文件头、几何体数、非空顶点、材质、贴图；再后处理，最后原子写入 `public/assets/models/<id>.glb`。
5. 每完成一项就落盘进度，`--resume` 只处理未完成或明确失败的记录；`encounters.json` 用按 `id` 合并 + 临时文件原子替换。提供 `--dry-run` 列出将提交的数量和预计费用。运行日志不打印 API 密钥或签名 URL。

先跑 20 条并留存失败清单；挑质量最好的 8 条作为演示场景。20 个高质量任务按当前两例**粗估**约 1,200 积分，实际价格以提交前账户计费为准。

## B3 归一化和性能

约定 Three.js 的 **Y-up、+Z 为正面**。对每个模型应用可审计变换：必要的人工正面 yaw 修正 → X/Z 居中 → 底面落到 Y=0 → 最长边缩放为 1；`model.bbox` 填后处理后的 `[宽,高,深]`。单视图不能可靠推断模型“正面”，精选的 8 个资产允许在清单里填 yaw 覆盖值。变换要保留 PBR 材质和纹理，并用前后预览对比确认。

当前原始 GLB 每个约 56–58 MB、约 190 万面，直接加载 8 个就超过 400 MB，不能当演示运行资产。保留原始件在缓存目录，另导出减面/压缩的前端 GLB；先以单件 3–5 MB、约 3–8 万面为试验目标，实际阈值由 A 在目标笔记本和手机上测帧率决定。后处理失败时宁可退回较大但可用的模型，不交损坏文件。

## B4 稀有度

文档同时写“常见度分”和“分数越高越稀有”，口径需统一。建议让 LLM 返回 `commonness: 0..100`（越高越常见），转换为 `baseRarity = 100 - commonness`，再算 `score = clamp(baseRarity + (firstSeen ? 15 : -30), 0, 100)`；按文档阈值映射 tier。按规范化后的 `label` 缓存 LLM 结果，同名不重复调用。该公式应由 Seven 确认后写成测试，避免“常见度高却评传奇”的反向错误。

LLM 响应必须有合法分数与非空定性 reason；含无来源统计数字、百分比、人数，或声称未提供的地点事实时拒绝。失败统一回退 `tier=uncommon, score=30, reason=暂未评级`。每条都写入 `tier/score/reason`，并留单元测试覆盖越界、空理由、数字编造和缓存命中。

## B5 离线演示包与 B6 打印

9/23 晚固定一个演示快照：`encounters.json`、精选 GLB、cutout、A 的 `stack.json`、预览截图及校验清单。断网后从本机启动站点，走完 1 分钟脚本至少 3 遍；不要依赖 Tripo CDN、LLM 或临时签名链接。

A 交付 `stack.json` 时双方先冻结坐标约定（同一 Y-up 空间、物件 id、position、quaternion、scale、底盘尺寸）。B 将精选模型按变换放置、统一毫米单位并加可打印底盘，优先出 3MF，必要时另出 STL；用切片软件检查开口、浮空件、厚度和实际尺寸。打印实体应提前完成，现场打印只算加分项。
